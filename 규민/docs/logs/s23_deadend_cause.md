## 1. 받은 쪽 24 vs 못 받은 쪽 14 비교 (frozen_v1)
노드 대응: 정의된 junction 의 name = OSM 노드 id. 정의 없는 junction 은 참조 road 참조선 끝점 최근접 변환 노드(거리 0.0m)
- OSM way 길이: 받음 중앙값 106m(58.6~395) / 못받음 118m(56.7~418). 겹침
- 태그 구성: 받음 parking_aisle 20·없음 3·lit 1 / 못받음 parking_aisle 10·footway=sidewalk 2·없음 2. 겹침
- 노드 수: 받음 4~19(중앙 6) / 못받음 2~31(중앙 6.5). 겹침
- 끝 노드가 다른 way 와 공유(변환 입력 OSM highway 기준): 받음 24곳 중 16곳 공유, 8곳 단독 / 못받음 14곳 중 9곳 공유, 5곳 단독. 겹침
- 도로 폭: 전부 차선 3.35 + 보도 2.80, 짝 반쪽도 같음. width·lanes 태그 0. 차이 없음
- oneway: 양쪽 다 0. 차이 없음
- 끝 노드 연결 차수: 변환 way 기준 양쪽 다 1. 입력 OSM highway 전체 기준 받음 1·2·3 / 못받음 1·2·3. 겹침
- 추가 비교도 갈리지 않음
  - 막다른 노드가 way 의 첫 노드인가 끝 노드인가: 받음 첫 12·끝 12, 못받음 첫 6·끝 8
  - 끝 구간 길이: 받음 8.7~123m, 못받음 3.5~107m
  - 끝점 기하: 들어가는 반쪽 끝과 나오는 반쪽 시작이 양쪽 다 0.00m, 방향 차 정확히 180°
  - 평활화: 평활화 전 tags73 맵도 같은 14곳이 빠짐. 평활화 원인 아님
- 같은 way 의 양 끝에서 갈린 사례: way468616610 은 한쪽 끝(j96)은 회차를 받고 다른 끝(j97)은 못 받았다.
  같은 태그·폭·oneway 인데 결과가 다르다 = way 속성이 원인이 아니다

## 4. 후처리 설계안 (구현 안 함)
### 근거
- frozen_v1 의 막다른 끝 회차 커넥터 24개는 전부 같은 틀이다(로그·인라인 검산)
  - paramPoly3 aU 0 / bU 14.9817 / cU -11.9853 / dU 0 / aV 0 / bV 0 / cV 5.9927 / dV 0, pRange normalized
  - 길이 9.89240086, laneOffset 3.35, lane -1 driving 3.35, lane -2 sidewalk 2.80, laneLink -1->-1, -2->-2
  - 들어오는 road 끝 기준 상대 위치·방향이 24개 모두 같다
- 정의 없는 junction 14개는 기존 road 가 이미 참조하고 있다(들어가는 반쪽 successor, 나오는 반쪽 predecessor)
  -> 기존 road 는 한 글자도 안 바꾸고 junction 정의와 커넥터 road 만 추가하면 된다

### 절차
1. 대상 맵(재변환 산출물)에서 정의 없는 junction 참조를 다시 뽑는다(frozen_v1 목록을 재사용하지 않는다)
2. 각 junction 마다 참조 road 2개 확인: successor 로 참조 = 들어가는 반쪽, predecessor 로 참조 = 나오는 반쪽.
   끝점 0.00m·방향 180° 가 아니면 건너뛰고 기록
3. junction 추가: id = 기존 참조 id, name = 그 자리 OSM 노드 id, connection 1개(incomingRoad=들어가는 반쪽,
   connectingRoad=새 road, contactPoint=start, laneLink -1->-1, -2->-2)
4. 커넥터 road 추가: 새 id(기존 최댓값+1부터), junction=위 id, name ":<노드id>_0",
   link predecessor=들어가는 반쪽(end), successor=나오는 반쪽(start), 위 계수 그대로.
   시작 x/y/hdg 는 기존 24개에서 잰 "들어오는 road 끝 기준 상대 변환"(상수)을 적용
5. 새 파일명으로 저장(예: ..._<날짜>_turnfix.xodr). 입력 파일과 frozen_v1 은 그대로
6. 검증
   - 오프라인 carla.Map: 들어가는 반쪽 lane -1 끝 next() -> 새 커넥터 -> 나오는 반쪽, 14곳 전부
   - 새 커넥터와 기존 템플릿 커넥터의 waypoint 위치·방향 차가 같은지(아래 결함까지 같은지)
   - s23_connectivity.py 재실행: 도달 불가 51 -> 0 기대, 갇힘 수 감소 확인
   - 서버 로드: road/junction 수 +14, to_opendrive 해시 = 파일 해시
