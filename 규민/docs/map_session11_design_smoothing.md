# 맵 세션11 Phase B — 평활화 설계 (조사·설계만, 정식 스크립트 미작성)

승인된 방향: 임계 반경 = 6.15m + 여유, 좌·우회전 구분 없이 모든 커브, 중문·후문 way 는 추가하지 않는다.

## 0. 설계에 영향을 준 실험 결과 (스크래치패드 실험, 스크립트는 map/scripts/exp_s11/)
1. 격리 재현: road1247 OSM 체인(way392532207, 8노드)만 떼어 변환하면 실제 망과 같은 결과
   (쌍둥이 road 2개, 해석적 R_min 1.78m vs 망 1.86m). 격리 실험이 유효하다
2. 지표 교정 (설계의 핵심): 변환기(paramPoly3)는 접합부에 곡률 스파이크를 만든다.
   - 해석적 순간 곡률 최소반경은 필렛 반경의 약 0.375배로 나와 판정 기준으로 부적합
   - CARLA 메시는 vertex_distance=2.0m(OpendriveGenerationParameters 기본값, 실측 확인)로
     샘플링하므로 폭 2m 미만 스파이크는 메시에 반영되지 않는다
   - 그래서 판정 지표를 "2m 창 평균 곡률"(R2, f2=1-6.15/R2)로 바꾼다.
     필렛 실험: 필렛 R 8/12/16/20 → 변환 후 R2 7.98/11.97/15.97/19.84 (오차 1% 이내)
3. 지표 교정 후 통과·정지 커브는 기하로 구분되지 않는다:
   s=80(통과) R2=6.12 f=-0.005 / s=95(정지) R2=6.08 f=-0.011. 둘 다 임계값 6.15m
   바로 위아래. 통과/정지 차이는 차량 횡위치(왼쪽 모서리 -0.19 vs +0.19)가 결정 변수라는
   Phase A 결과와 정합. 평활화 후 재검증에서 어느 쪽인지 가려진다
4. 변환기는 꺾임 하나(세그먼트 12m 이상)는 스스로 다듬는다(28.5°→R2 18.7m). 실제 체인이
   R2 6.1m 로 나쁜 것은 4.07m 짧은 세그먼트와 공선 노드 등 노드 군집 때문이다.
   → 각도만으로 대상을 고르면 안 된다(꺾임 10° 이상 노드 492개 중 실제 원인은 71개, 14%)
5. 그래서 "변환 → 측정 → 문제 노드만 필렛 → 재변환 → 검증" 구조를 쓴다(측정 기반 선택)

## B-1. 목표 반경과 여유 근거
- 물리 임계: 기준선~인도 바깥 6.15m (차선 3.35 + 인도 2.80). 이보다 작으면 안쪽 인도 오프셋이 접힌다
- 수용 기준: f2 >= 0.30  <=>  R2 >= 6.15/0.70 = 8.79m
  - 근거: f 는 안쪽 인도 가장자리 곡선이 기준선 진행 대비 몇 배로 압축되는지. f=0 이 접힘 경계.
    CARLA 는 2m 간격 정점으로 메시를 만들므로 f=0.30 이면 인도 바깥 정점 간격이 0.6m 로
    2m 대비 30% 는 유지된다. **0.30 은 공학적 선택값이며 CARLA 내부에서 도출한 값이 아니다.**
    주행 재검증으로만 확인 가능
- 필렛 목표 R_T = 11.0m, 수용 하한 R_ACC = 10.0m
  - 변환기 손실: 합성 실험 0.99~1.00, 실제 경로 커브(노드 3957495733/32) R_T=10 에서 0.95/0.91.
    최악 0.91 로 8.79/0.91 = 9.7 → R_ACC = 10.0
  - R_T 스윕(이탈 상한 2m): R_T=9 이면 f 0.2~0.3 경계 구간이 98곳(경계 미달 다수),
    10~12 는 잔여 구간 수가 거의 같다(이탈 상한 없이 R_T 10/11/12 = 40/39/40곳,
    2m 상한 적용 시 65/66/70곳). R_T=11 에서 경로 핵심 두
    커브 f=+0.42/+0.40 (R_T=10: 0.35/0.32, 12: 0.45/0.48). R_T=14 이상은 s=80 커브에서
    이웃 노드 4.07m 제약으로 필렛이 성립하지 않아(R2 6.1m 그대로) 상한은 약 12
  - 여유 합계: 11.0 - 6.15 = 4.85m = 접힘 경계 -> 수용 기준 2.64m + 변환기 손실 0.9m
    + 목표 헤드룸 1.3m
- 좌·우회전 무관: 쌍둥이 매핑(plain road 260개 중 240개)으로 한쪽 인도가 항상 안쪽이므로
  대상 판정에 회전 방향을 쓰지 않고 xodr 스캔 결과(안쪽 인도 f2)로만 판정한다

## B-2. 보간 방법
- 꺾이는 노드를 반경 R 원호로 모따기(fillet). 접선 길이 T = R*tan(θ/2), 호 위 노드 간격 2.0m
  (h=1/2/3m 스윕에서 결과 차이 1% 이내), 꼭짓점 삭제 후 접선점~호~접선점 노드 삽입
- 인접 필렛 접선 길이 합이 사이 거리를 넘으면 R 을 축소, R_ACC 미만이 되면 그 노드는 건너뛴다
  (부분 필렛은 R2 가 기준에 못 미치고 부작용만 생김)
- 접선 영역 안에 있는 꺾임 10° 미만 비목표 노드는 삭제(흡수). 시험에서는 1개
- 원본 이탈 계산: 꼭짓점~호 중점 거리 R*(sec(θ/2)-1) 로 대상 선정 시 상한(D_MAX) 판정,
  결과는 원본/신규 폴리라인 양방향 Hausdorff 거리로 측정
- **이탈 상한 D_MAX** (사용자 결정 필요): 직각 코너(θ~90°) 는 R=11 에서 이탈 4.6m
  | 옵션 | 필렛 수 | 문제 구간(f<0.3) | 최대 이탈 |
  | 없음 | 53 (R_T=10) | 89 -> 46 | 4.68m (2m 초과 14 way) |
  | 2m (권장) | 34 | 89 -> 64 | 1.99m (중앙 0.53) |
  | 1m | 30 | 89 -> 71 | 0.93m |
  3m 은 2m 과 결과가 같아 의미 없다. 권장 2m 근거: 차선폭 3.35m 의 약 60%,
  OSM 원본 위치 정밀도(세션9 정렬 잔차 RMS 3.7m)보다 작아 위치 신뢰도를 해치지 않는 범위
- 건물 침범(OSM 건물 폴리곤 399개, 원본 OSM): 중심선이 건물 내부로 들어가는 곳 신규 0곳.
  인도 포함 반폭 6.15m 이내로 가까워져 원본보다 0.05m 이상 악화되는 곳 1곳(옵션 2m).
  원본에서 이미 6.15m 이내인 곳은 22곳(기존 상태)

## B-3. 적용 범위
- 전체 도로망(485 way 파일 전체)에 적용, 임계 이하만: 측정 기반이라 f2>=0.30 인 멀쩡한 곡선은
  대상에서 빠진다(시험: 후보 각도 8° 이상 노드 중 필렛 34개)
- 고정 노드는 건드리지 않는다: 다른 way 와 공유되거나 way 끝점인 노드, 그 2m 이내.
  (실험: 필렛이 junction 노드 4m 안까지 와서 junction 클러스터가 병합돼 road 878->874,
  junction 95->94 로 위상이 바뀐 사례 발생. 고정 노드 2m 여유와 R_ACC 미달 건너뛰기를
  넣자 878/95, junction 이름 집합 동일)
- 시험 결과(권장 옵션, 이탈 2m, R_T=11, R_ACC=10): 문제 구간 89 -> 64, 접힘(f<0) 58 -> 43.
  road/junction 878/95 유지. **경로 위 물리 문제 구간 2곳(road1247 두 커브)은 해소**
- **잔여 64곳은 이번 방법으로 못 푼다**: 원본 내부노드지만 이탈 상한 초과(직각 코너 등) 33,
  고정 노드/junction 근처 28, 군집·호 근처 3. 경로 밖이지만 중문·후문 경로가 지나가면
  다시 문제가 된다. 정직한 한계다 -> 보고서에 잔여 목록을 남기고 그때 대응
- 직접 원인 미확정(접촉면 후보 a/b)이므로 재검증은 주행이다

## 스크립트 구성안 (승인 후 map/scripts/ 에 작성)
1. curve_metrics.py (공용): lane 파싱, 2m창 지표 R2/f2, 쌍둥이 탐색, xodr 스캔
   - parse_lanes / lane_edges / window_metrics / find_twins / scan_sites
2. smooth_osm_curves.py (파이프라인 단계)
   - 목적: 문제 노드만 필렛한 OSM 사본과 변경 로그 생성
   - 데이터 흐름: 입력 OSM -> (1) 원본 변환(임시) -> (2) scan_sites -> (3) ICP 로 문제 위치를
     OSM 노드에 대응 -> (4) select_targets -> (5) plan_fillets(제약·축소·건너뛰기) ->
     (6) 사본 OSM 작성 + 로그 -> (7) 재변환·검증 후 잔여 있으면 최대 3회 반복
   - 핵심 함수: align_icp, select_targets, plan_fillets, fillet_vertex, write_osm, deviation
3. verify_smoothing.py: 재변환 후 검증 (문제 구간 재측정, road/junction 수, junction 이름 집합,
   축척 비율, 경로 존재·길이, 건물 침범, 이탈)
4. osm_to_xodr.py 는 입력/출력 경로 인자 추가만(기본값 불변)

## 위험과 한계
- R2 는 메시 스케일 대리 지표이며 CARLA 에서 검증되지 않았다(주행 재검증 필요)
- ICP 정렬 중앙 잔차 0.16m. 평행 way 사이에서 오매칭 가능 -> 거리 1.5m 초과는 제외·로그
- ENU 근사(등장방형) 좌표 사용, tmerc 대비 축척 0.997: 반경 0.3% 오차, 무시 가능
- 쌍둥이 way 는 하나의 OSM way 를 공유하므로 필렛은 양방향에 동시에 적용된다
- 이 사전 실험은 스크래치패드 시험이며 프로젝트 OSM/xodr 파일은 변경하지 않았다
