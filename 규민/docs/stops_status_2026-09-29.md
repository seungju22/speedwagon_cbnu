## 정류장 두 유형 (노선 구조)
결론: 정류장은 "통과형"과 "종점형" 두 종류다. 이것은 맵의 약점이 아니라 캠퍼스 도로가 생긴 모양이다.

- 통과형 = 남문, 양성재
  - 뜻: 정류장이 "U턴 없이 서로 오갈 수 있는 도로망"(핵심 도로망) 위에 있다. 차가 서고 나서 그대로 앞으로 가면 다음 정류장으로 간다
  - 근거: U턴형 커넥터 143개를 뺀 방향 그래프의 최대 강연결 성분(441 road)에 두 정차 road 가 들어 있다
    (s19_scope.log). 남문 -> 양성재 903m, 양성재 -> 남문 1147m 모두 U턴 없음
- 종점형 = 북문, 중문, 후문
  - 뜻: 정차점이 막다른 길(가지) 끝 쪽에 있다. 서고 나서 다른 곳으로 가려면 길 끝에서 한 번 돌아 나와야 한다(회차)
  - 근거 1: 세 정차 road 모두 핵심 도로망 밖. 북문 road1378 끝은 j109(커넥터 1개짜리 막다른 끝 회차 r1665),
    중문 road1327 끝은 j87(회차 r1840), 후문(시험 맵) r1171 끝은 j4(회차 r1442, 1순환로 접점 바로 앞)
  - 근거 2 (way 전수 확인): 변환에서 빠진 캠퍼스 안 service way 145개를 하나씩 추가해 보는 OSM 방향 그래프 실험에서
    세 정류장 중 어느 것도 U턴 없이 정문으로 나가는 길이 생기지 않았다. 즉 "way 하나를 빠뜨려서 막힌 것"이 아니라
    실제로 막다른 길이다 (s19_scope.py "종점형 전수", s19_scope.log)
  - 회차 방법(확정): 막다른 길 끝의 회차 커넥터만 쓴다. 교차로 한가운데 U턴(j42 r1449, j10 r1429, j60 r1697, j1 r1915)은
    쓰지 않는다. 세션13 에서 Traffic Manager 가 이 교차로 U턴 커넥터를 골라 주행이 망가진 전례가 있고, 실제 셔틀도 종점에서 돌아 나온다
  - 주의: 회차 커넥터는 전부 같은 틀(길이 9.89m, 평균 반경 4.47m)이다. 두 차선 폭(6.7m) 안에서 180° 도는 모양이라
    실제 차가 한 번에 돌 수 있는지는 미검증
- 정문
  - 지금은 들어오기만 가능하다. 정문 안쪽 구간에 나란히 있는 일방통행 way 4개 중 들어오는 1개만 변환됐다
  - 재변환 때 나가는 way 481950060 을 넣기로 확정. 넣으면 정문을 지나는 U턴 없는 순환이 생긴다고 예측(965m, OSM 수준).
    재변환 후 그 순환이 캠퍼스 안에서 닫히는지(밖 공도로 나갔다 들어오지 않는지) 확인해야 셔틀 노선으로 쓸 수 있다

### TTC 임계값 유도 (인용 대신 우리 차량 값으로)
- 상황: 속도 v 로 가다가 앞에 멈춰 선 보행자를 발견. 발견 순간 거리 d, TTC = d / v
- 멈추는 데 필요한 거리 = 지연 동안 가는 거리 + 제동 거리 = v x t_d + v^2 / (2a)
- 따라서 부딪히지 않고 설 수 있는 최소 TTC:  TTC* = t_d + v / (2a)
  - t_d = 인지 지연 + 판단 지연 + 제동 작동 지연
  - a = 우리 차량의 실측 최대 감속도(m/s^2)
- v = 20km/h = 5.56m/s
- 지금 있는 값(부분 측정, 확정값 아님)
  - 제동 작동 지연(추정): south 종점에서 brake=1.0 명령 뒤 약 0.1s 동안 속도가 오히려 올랐다(5.35 -> 5.78m/s). 약 0.1~0.15s. 세션20 은 지연보다 속도 튐 구간으로 해석 [세션26-B]
  - 감속도: north 종점 brake=1.0 구간 0.2s 동안 6.4m/s^2, south 0.2s 동안 3.7m/s^2. 둘 다 제동 시작 직후 0.3s 뿐이고
    판정과 함께 시뮬이 끝나 끝까지 선 기록이 없다 -> 측정 예정
  - 인지 지연: 인지 모듈이 없어 측정 예정. 시뮬 1 tick = 0.05s 가 하한
- 예시 계산(식 확인용, 목표로 쓰지 않음): t_d = 0.15s(작동 지연 + 1 tick), a = 3.7 이면 TTC* = 0.15 + 5.56/7.4 = 0.90s,
  a = 6.4 이면 0.58s. 인지 지연이 0.5s 더 붙으면 각각 1.40s, 1.08s
- 목표값 세우는 법: 감속도 a 와 지연 t_d 를 정지 시험(20km/h 에서 brake=1.0, 완전 정지까지 기록)으로 측정한 뒤
  TTC 목표 = TTC* x 안전계수(예 1.5). 측정 전까지 목표 칸은 "측정 예정"
- 세션20 실측(map/tests/test_brake.py, 평지, 3s 정속 뒤 20km/h 이상이 된 첫 tick 에 brake 1.0, 5회, 로그 brake_test_20261002_013158_hold3.csv)
  - 정지 시간 0.95~1.00s, 정지거리 3.78~4.00m, 정상 구간 감속도 6.42±0.10m/s^2, 명령 뒤 0.10s 동안 속도가 더 오름(차량 모델의 속도 튐 구간)

  - TTC 기준 0.70s = 정지거리/속도(거리 기준 환산. 제동 시간이 아니다. 실제 정지 0.95~1.00s) [세션26-B]. 5.56m/s 로 환산한 정지거리 0.70 x 5.56 = 3.89m
  - TTC 1.2s 일 때 간격 1.2 x 5.56 = 6.67m, 여유 6.67 - 3.89 = 2.78m = 시간으로 2.78 / 5.56 = 0.50s
  - 결론: TTC 1.2s 는 TTC 기준 0.70s 의 1.7배(1.2/0.70 = 1.71)이며 인지·판단 지연 0.50s 까지 견딘다
  - 시간 기준 여유 [세션26-B]: 1.2 - (0.95~1.00) = 0.20~0.25s = 정지 완료가 충돌 예상 시각보다 앞서는 시간. 허용 지연 0.50s(거리 기준)와 다른 값
  - 검산 정정: 지시문의 "역산 감속도 3.97m/s^2, 정지시간 1.40s" 는 3.89m 를 처음부터 끝까지 같은 감속도로 섰다고 가정한 환산값
    (a = v^2/2d, t = v/a)이고 실측과 다르다. 실측 정지시간은 0.95~1.00s, 정상 구간 감속도 6.42m/s^2 다.
    차이는 명령 직후 0.10s 동안 속도가 오히려 오르는 구간(아래 속도 진동) 때문이다. 근거 문장에서는 두 값을 빼고 실측 정지거리·시간만 쓴다
  - "평균 3.89m" 정정: 3.89 는 범위 3.78~4.00 의 중간값(그리고 0.70s 를 5.56m/s 로 환산한 값)이다. 5회 산술 평균은 3.93m
