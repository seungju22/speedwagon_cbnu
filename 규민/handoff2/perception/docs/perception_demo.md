# 인지 데모 요약 (세션58~60, 2026-10-14~15)

캠퍼스 v3.1 지도, CARLA 0.9.15 + Autoware 1.9.0(정답 측위), 노선 구간 p_middle_north(중문 -> 도서관 북문, 268m), 장식 레이어 732 켬.
인지는 정답 객체 노드 gt_objects2.py 두 모드로 바꿔 끼웠음. 다 보기 = 80m 안 모두, 차 시점 = 지붕 LiDAR 에서 거리·시야·가려짐을 넘은 것만.
모든 회차 실시간 0.998배.

## 차 시점 거리와 근거
- 보행자 17.5m, 차량 35m, 표시 단 소품(콘) 12.5m. LiDAR 자리에서 물체 중심까지
- 정한 법: 기준 센서(브리지 기본 LiDAR 64채널, 초당 30만 점, 20Hz, 100m, 센서 킷 자리, 무작위 버림·노이즈 0)를 단 차를 곧은 길 두 곳에 세우고,
  물체를 하나씩 놓아 시맨틱 LiDAR 가 그 물체에 맞힌 점 수를 셌음. 10점 이상(Autoware 클러스터링 최소 점 수) 가장 먼 거리
- 보수적임: 한 바퀴 1만 5천 점이라 실제 센서(VLP-16 약 3만, OS1-64 약 6.5만)보다 성김
- 가까운 쪽 한계 없음: 차 옆 0.3~3m(문 구역 자리) 보행자에 78~298점, 앞 범퍼 0.5m 보행자 104점
- 센서 기준 확정(세션60, 백로그 S1 닫음): 15km/h 에서 반응 1초 + 감속 1.0m/s2 로 서는 거리 12.9m 안 보행자에 10점 이상을 끝 기준으로 했음.
  보행자는 17.7m 까지 10점 이상이라 넘고, 콘은 12.7m 까지라 조금 못 미침. 원래 기준(20m 보행자 10점)은 못 맞췄음
- 처음(세션58)에 쓴 7.5 / 20 / 6m 는 32채널·초당 10만 점 '가벼운 LiDAR' 값이라 쓰지 않음
- 시뮬레이터 LiDAR 도 64채널·30만 점으로 바꿨음. 실시간 0.998배 그대로, 주행 중 최소 가용 메모리 2.4GiB(이전 2.8GiB)

- 다1 가벼운 LiDAR 는 세션58 의 콘+걸친 차 한 장면(콘이 앞) 결과임. 다2 가벼운 LiDAR 는 돌리지 않았음
- 거리: 가는 앞 범퍼에서 보행자까지(차로 방향), 다는 LiDAR 에서 물체까지. 남은 거리는 차로 따라 근사
- 가: 보행자는 차로 밖 밴 뒤에서 1.4m/s 로 나와 건넘(자차 20m 안에서 출발). 기준 센서 거리면 출발 0.75s 뒤 잡혀 다 보기와 거의 같음
- 다2: 두 모드 모두 Autoware 회피 모듈이 차선 안에서 왼쪽으로 0.4m 옮겼음. 다 보기는 그 뒤 obstacle_stop 이 차 몸통을 여유 안으로 보고 세웠고,
  차 시점은 같은 물체를 계속 받고도 서지 않고 지나갔음(세션60 에 두 모드 다시 돌려 같은 결과)
- 다2 원인(세션60): 회피 경로가 걸친 차 옆을 지나는 간격이 0.30~0.35m(근사)로 obstacle_stop 옆 여유 0.3m 경계에 걸쳐 있음.
  다 보기는 0.4m 이동이 차 14.5m 앞에서 확정되며 궤적 간격 0.31m 로 정지 판정이 났고, 차 시점은 차가 34.8m 에서야 보여 이동이 6m 앞에서 확정됐고
  간격이 0.30m 에 닿은 때는 이미 차 옆이라 서지 않았음. 인지 출력은 두 모드가 같은 상자를 빠짐없이 냈음. Autoware 계획 쪽 경계 판정이라 고치지 않았음

## 문 구역 결과 (나)
- 북문 승강장 정차 뒤 하차 -> 문 구역 5초 -> 전방 통로 들어왔다 나가기 -> 탑승(보행자 도구 ped_tool.py)
- 정차 위치 오차: 문이 목표보다 0.45m 뒤(문 구역 앞뒤 3.0m 안), 옆 0.00m
- 문 구역 안 보행자를 차 시점이 놓친 것은 새로 생긴 보행자의 첫 1틱(0.05s)뿐임(세션60 다시 돌린 회차도 두 보행자 첫 1틱씩, 0.10 / 7.4s). 지붕 LiDAR 가 문 옆 0.3m 까지 맞혀 가까운 쪽 사각이 없음
- 출발 조건(문 구역·전방 통로 비었는지)에 차 시점 인지를 써도 된다는 근거로 쓸 수 있음. 단 새 물체는 정답 목록 갱신 때문에 최대 1초 늦게 들어옴

## 실제 LiDAR 클러스터링과 비교 (문 구역, 오프라인, 세션59·60)
- 회차 점군을 Autoware 1.9.0 지면 분할(scan_ground_filter) + voxel_grid_based_euclidean_cluster(기본 설정)에 넣고 보행자 정답과 맞췄음(중심 1.0m 안, 10Hz)
- 세션59 는 브리지 LiDAR(무작위 버림 0.45)라 거리 기준(버림 0)과 조건이 달랐음. 세션60 에 같은 장면을 다시 돌리며 같은 자리에 버림 0 기준 LiDAR 를 따로 달아 기록했음

| 점군 | 문 구역 잡음(놓침) | 전방 통로 잡음(놓침) | 보행자 점 수(문 / 통로) |
|---|---|---|---|
| 버림 0.45(세션59) | 74/82 90%(0.8s) | 46/51 90%(0.5s) | 126 / 14 |
| 버림 0.45(세션60) | 80/84 95%(0.4s) | 46/51 90%(0.5s) | 124 / 14 |
| 버림 0(세션60, 기준) | 78/82 95%(0.4s) | 51/51 100%(0) | 223 / 25 |
| 버림 0 + 정류장 시설 점 지움 | 82/82 100%(0) | 51/51 100%(0) | 223 / 25 |

- 전방 통로 놓침은 버림 탓임. 버림 0 이면 보행자 점이 25개라 최소 10점 밑으로 안 떨어짐
- 문 구역 놓침은 버림과 상관없음. 보행자가 정류장 시설(높이 2.3m, 900~1,600점)과 한 클러스터로 붙어 중심이 2m 밀림.
  노선 파일의 시설 자리로 시설 점을 지우면 놓침 0 이 됨(오프라인 확인만, 주행 중 Autoware 에는 안 넣음)
- 차 시점(정답 + 거리·가려짐) 놓침은 문 구역 0.05~0.10s, 전방 통로 0 임. 기준 LiDAR 클러스터링에 시설 점 지움까지 한 경우와 같은 수준이고,
  시설을 안 지운 실제 클러스터링보다는 낙관적임
